# Research: "Herder" = **Herdr** (herdr.dev)

*Researched 2026-09-09. All facts come from pages fetched today. Each claim has its source link.*

## Summary (the short version)

1. The product Anthony demoed is **Herdr** (spelled H-E-R-D-R). Site: https://herdr.dev. Code: https://github.com/herdrdev/herdr.
2. **herder.dev** (with the "e") is a parked "for sale" domain, not the product (https://herder.dev redirects to a GoDaddy sale page). **herdr.ai** is also for sale. I am very sure Herdr is the right product: every feature Anthony described matches the docs.
3. Herdr is "the runtime coding agents run on": a **terminal multiplexer** (like tmux) built for AI coding agents. One Rust binary, no Electron ([herdr.dev](https://herdr.dev/), [GitHub README](https://github.com/herdrdev/herdr)).
4. It runs a **background server**. Close your laptop, lose SSH, come back later, and the agents are still running ([docs/session-state](https://herdr.dev/docs/session-state/)).
5. It is split into **workspaces** (called "Spaces" in the sidebar), one per repo/project ([docs/concepts](https://herdr.dev/docs/concepts/)).
6. It **detects 20+ agents** (Claude Code, Codex, pi, OpenCode, Cursor...) and shows each one as working / blocked / done / idle ([docs/agents](https://herdr.dev/docs/agents/)).
7. It plays a **sound** ("ding") when a background agent finishes or needs input. Sound is on by default ([config-reference](https://herdr.dev/docs/config-reference/)).
8. Agents can **spawn and steer other agents** through a CLI + socket API. This is how the "coordinator + sub-agents" view works ([docs/agent-automation](https://herdr.dev/docs/agent-automation/)).
9. **Free, open source, Apache 2.0**. ~37k GitHub stars. Made by Herdr, Inc. (founder Can Celik). Y Combinator F26 batch. Raised a $6M seed on Sep 8, 2026 ([blog](https://herdr.dev/blog/herdr-raised-a-seed/)). "Herdr Cloud" is paid and "coming soon" ([herdr.dev](https://herdr.dev/)).
10. Phone control works through any SSH app, but the nicest way is the **Moshi** app, which understands Herdr workspaces ([getmoshi.app/guides/herdr](https://getmoshi.app/guides/herdr)).

## 1. What it is, who makes it, license, pricing, install, platforms

### What it is
- Tagline: "the runtime coding agents run on" ([herdr.dev](https://herdr.dev/)).
- Simple picture: **tmux, but rebuilt for coding agents**. It keeps terminals running in a background server, and it knows which terminal has an agent and what that agent is doing ([flaviocopes.com/herdr](https://flaviocopes.com/herdr/)).
- It is NOT a terminal app like Ghostty or Warp. It runs *inside* your existing terminal. README: "One rust binary, no electron — runs in whatever terminal you already use" ([GitHub README](https://github.com/herdrdev/herdr)).
- It does **not** wrap the agent CLIs. You just type `claude` or `pi` in a pane and Herdr detects it ([docs/quick-start](https://herdr.dev/docs/quick-start/)).

### Who makes it
- Founder: **Can Celik** (@cancelik on X, GitHub `ogulcancelik`). It started as his solo personal project ([YC blog post](https://herdr.dev/blog/herdr-is-joining-y-combinator/)).
- Company: **Herdr, Inc.** ([herdr.dev footer](https://herdr.dev/)).
- Joined **Y Combinator** (F26 batch), announced Aug 6, 2026. At that time: 25k stars, 340k downloads ([YC blog post](https://herdr.dev/blog/herdr-is-joining-y-combinator/)).
- Raised a **$6M seed led by Bessemer Venture Partners**, with YC, e2vc, and angels (Tobi Lütke and others), announced Sep 8, 2026 ([seed blog post](https://herdr.dev/blog/herdr-raised-a-seed/)).

### License
- **Apache 2.0**. It was AGPL before. The founder switched it: "I want everyone to use Herdr freely" ([YC blog post](https://herdr.dev/blog/herdr-is-joining-y-combinator/), [GitHub](https://github.com/herdrdev/herdr)).

### Pricing
- The tool is **free** (open source). There is no pricing page with tiers today. The site says "Herdr Cloud" is "coming soon" with a waitlist: "Connect your own machines to Herdr without configuring SSH" ([herdr.dev](https://herdr.dev/), [herdr.dev/pricing](https://herdr.dev/pricing/)).
- The founder says: Cloud "connects them; it doesn't host the agents for you" ([0.9 blog post](https://herdr.dev/blog/connecting-the-machines/)).
- Some third-party "review" sites list a $29/month cloud plan. I could not find this on any official page. Treat it as **not confirmed** ([search result summary](https://www.stork.ai/en/herdr)).

### Install
From [docs/install](https://herdr.dev/docs/install/):
```
curl -fsSL https://herdr.dev/install.sh | sh      # macOS + Linux
brew install herdr                                # Homebrew
mise use -g herdr                                 # mise
powershell -ExecutionPolicy Bypass -c "irm https://herdr.dev/install.ps1 | iex"   # Windows
nix run github:herdrdev/herdr/v0.x.y              # Nix, from source
herdr update                                      # update later
herdr channel set preview                         # optional preview builds
```

### Platforms
- Stable binaries for **Linux, macOS, Windows x86_64** ([docs/install](https://herdr.dev/docs/install/)).
- Windows became "generally available" in v0.8.2 (Aug 19, 2026) ([releases](https://github.com/herdrdev/herdr/releases)).
- Multi-machine mode (see below) works only on **Linux and macOS clients**. Windows can only use the simpler `herdr --remote` ([docs/connecting-machines](https://herdr.dev/docs/connecting-machines/)).
- Current version: **v0.9.0** (Sep 7, 2026) ([releases](https://github.com/herdrdev/herdr/releases)).

## 2. Architecture

### Server / client model
- "The server owns panes and process state. The client is the terminal UI attached to that server." Many clients can attach to one server and look at different workspaces ([docs/concepts](https://herdr.dev/docs/concepts/)).
- Since 0.9: "Herdr's outer UI is rendered on the client. The servers still own their sessions and supply the terminal views." This is what lets one client show many machines ([0.9 blog](https://herdr.dev/blog/connecting-the-machines/)).
- Easy example: the server is like a kitchen that keeps cooking. The client is a window you look through. Close the window, the kitchen keeps working.

### Session persistence (this is what Anthony meant by "if your computer turns off you resume right away")
There are 3 levels ([docs/session-state](https://herdr.dev/docs/session-state/)):

| Case | Processes keep running? | Layout back? | Agent chat back? |
|---|---|---|---|
| Detach / close terminal / SSH drops | **Yes** | Yes | Yes (never stopped) |
| Herdr server restarts (reboot) | No | Yes | Only with agent integration installed |
| Pane history (experimental) | No | Yes | Shows old screen text |

- Detach: press `prefix+q` or just close the window. "agents continue running." Run `herdr` again to reconnect ([docs/quick-start](https://herdr.dev/docs/quick-start/)).
- After a real restart, Herdr restores "the saved session shape" (workspaces, tabs, panes, folders) and can **resume agent chats** with `claude --resume <id>`, `pi --session <id>`, etc. Setting: `[session] resume_agents_on_restore = true` (default true) ([docs/session-state](https://herdr.dev/docs/session-state/), [config-reference](https://herdr.dev/docs/config-reference/)).
- Important: resume only works if you ran `herdr integration install claude` (or `pi`) first. Without it, "rebooting leaves panes as empty shells" ([lasergoat gist](https://gist.github.com/lasergoat/7f92d7c4ba72ee9889bb4b1fd6cd287a)).
- Pane history is **off by default** "because pane output can include secrets, tokens, prompts" ([docs/session-state](https://herdr.dev/docs/session-state/)).

### Remote / multi-machine / phone
- Simple remote: `herdr --remote workbox` attaches to a Herdr server on another machine over SSH. "Your local Herdr draws the UI, including its sidebar, menus, and theme" ([docs/persistence-remote](https://herdr.dev/docs/persistence-remote/)).
- Multi-machine (v0.9): `herdr machine add workbox --label "Build machine"`. Saved machines show in the sidebar. You switch between them in one window. "The agents keep running on their own machines when you disconnect" ([docs/connecting-machines](https://herdr.dev/docs/connecting-machines/), [0.9 blog](https://herdr.dev/blog/connecting-the-machines/)).
- Limit today: "the agent CLI still works within one server. It doesn't yet see the agents running on your other machines" ([0.9 blog](https://herdr.dev/blog/connecting-the-machines/)).
- Reconnect: "bounded backoff" and keepalives. "a broken connection does not stay Online indefinitely" ([docs/connecting-machines](https://herdr.dev/docs/connecting-machines/)).
- Phone: Herdr itself has no phone app. You use an SSH app. The **Moshi** app (iOS/Android) is built for it: pick a workspace from the connect screen, get push notifications "tagged kind=herdr", and tap to jump to the exact tab the agent is waiting in ([getmoshi.app/guides/herdr](https://getmoshi.app/guides/herdr)). Moshi is free; Pro is $7.99/month or $69.99/year ([getmoshi.app/pricing](https://getmoshi.app/pricing)).
- Security note: "Herdr does not copy local command plugins, configuration, executables, or secrets onto SSH hosts" ([docs/connecting-machines](https://herdr.dev/docs/connecting-machines/)).

### Workspaces ("Spaces")
- "A workspace is the top-level project container. Use one workspace per repo, task, or investigation." Inside: tabs (layouts) and panes (real terminals) ([docs/concepts](https://herdr.dev/docs/concepts/)).
- The sidebar section is named "spaces" in config: `[ui.sidebar.spaces]` ([docs/configuration](https://herdr.dev/docs/configuration/)).
- Per-workspace env: `herdr workspace create --cwd ~/project --label api --env KEY=VALUE` (repeatable). Same for tabs ([docs/cli-reference](https://herdr.dev/docs/cli-reference/)).
- **About "own aliases, git/LLM accounts per space"**: I did not find a built-in Herdr feature for this. What exists is `--env` per workspace/tab. You could set things like `GIT_CONFIG_GLOBAL` or an API key env var per workspace, and your shell rc can read it. Community plugins (herdr-plus, herdr-compose, herdr-spreader) add declarative per-workspace layouts and env ([herdr-compose](https://github.com/ropali/herdr-compose), [herdr-spreader](https://github.com/yuk1ty/herdr-spreader)). **Not sure** exactly how Anthony set his up. Ask him.
- Git worktrees are built in: `herdr worktree create --branch NAME` makes a worktree, opens it as a workspace, and groups it with the parent repo workspace. Root folder: `[worktrees] directory = "~/.herdr/worktrees"` ([docs/cli-reference](https://herdr.dev/docs/cli-reference/), [config-reference](https://herdr.dev/docs/config-reference/)).

### Notifications and sounds (the "ding")
From [config-reference](https://herdr.dev/docs/config-reference/):
- `[ui.sound] enabled = true` (default). "Play sounds when agents change state in background workspaces."
- Two sounds: **done** (agent finished a turn) and **request** (agent is blocked / needs input). You can set your own mp3: `path`, `done_path`, `request_path`.
- Per-agent on/off: `ui.sound.agents.claude`, `ui.sound.agents.pi`, etc. (Droid is off by default.)
- Popups: `[ui.toast] delivery = "off"` by default. Options: `herdr` (in-app toast), `terminal`, `system` (OS notification). `delay_seconds = 1` so it only fires if the agent is still in that state after 1 second.
- Notifications are focus-aware: the tab you are looking at does not ding. "It alerts you about work you are not already watching" ([flaviocopes.com/herdr](https://flaviocopes.com/herdr/)).
- CLI: `herdr notification show --body TEXT --sound done|request` ([docs/cli-reference](https://herdr.dev/docs/cli-reference/)).

### How it hosts agents (pi, Claude Code, Codex...)
- Detection: Herdr "identifies the foreground process and reads the live bottom-buffer screen snapshot" and matches it against TOML "screen manifest" rules. States: working, blocked, done, idle, unknown ([docs/agents](https://herdr.dev/docs/agents/)).
- Two integration types ([docs/integrations](https://herdr.dev/docs/integrations/)):
  - **Lifecycle authority** (exact state from hooks): Pi, OMP, Kimi, OpenCode, Kilo, MastraCode.
  - **Session identity only** (Herdr learns the session id so it can resume, but state still comes from the screen): **Claude Code**, Codex, Copilot, Devin, Droid, Cursor, Qwen, Grok, and more.
- Claude Code integration installs a hook at `~/.claude/hooks/herdr-agent-state.sh` and gives "Session identity reporting only; state from screen detection" ([docs/integrations](https://herdr.dev/docs/integrations/)).
- Pi: `herdr integration install pi` installs `~/.pi/agent/extensions/herdr-agent-state.ts`. There is also a community pi package, `pi install npm:@andrewjacop/pi-herdr`, that turns pi into an **orchestrator**: "spawn another pi, claude, codex, or opencode in its own terminal pane, send it a prompt, wait for it to finish, and harvest its response" ([pi.dev package](https://pi.dev/packages/@andrewjacop/pi-herdr?name=web)). This matches what Anthony showed (pi as coordinator, sub-agents in panes).
- Coordinator flow commands ([docs/agent-automation](https://herdr.dev/docs/agent-automation/)):
```
herdr agent start reviewer --kind codex --pane "$review_pane" -- -m gpt-5.4
herdr agent prompt reviewer "Review the current diff" --wait --timeout 120000
herdr agent wait reviewer --until blocked --timeout 120000
herdr agent read reviewer --source recent-unwrapped --lines 120
herdr agent attach reviewer          # click into a sub-agent and steer it
```
- Debug detection: `herdr agent explain <target>` ([docs/agents](https://herdr.dev/docs/agents/)).

**Security** (there is no dedicated security page; these are the facts spread across docs):
- Herdr "does not sandbox your agents." You still own access control ([coles.codes](https://coles.codes/posts/herding-agents-with-herdr/)).
- Early issue #4 (Apr 2026): the Unix socket was world-readable, so "Any local user can send commands, read pane output." The issue is now **closed**; I could not see the fix text on the page ([issue #4](https://github.com/herdrdev/herdr/issues/4)). On a single-user laptop this matters less.
- Remote uses "your normal OpenSSH authentication." Secrets are not copied to remote hosts ([docs/persistence-remote](https://herdr.dev/docs/persistence-remote/), [docs/connecting-machines](https://herdr.dev/docs/connecting-machines/)).
- Pane history off by default because of secrets ([docs/session-state](https://herdr.dev/docs/session-state/)).
- Socket API docs do not mention auth; access relies on local socket file permissions ([docs/socket-api](https://herdr.dev/docs/socket-api/)).

Then open the session on claude.ai/code or the Claude iOS/Android app by URL or QR code. Your machine keeps running the code; the phone is a window. "if your laptop sleeps or your network drops, Claude Code reconnects automatically when your machine comes back online." Server mode has `--spawn worktree` so each phone-started session gets its own worktree. Needs Pro/Max/Team/Enterprise; API keys not supported. Limit: one remote session per interactive process; after you stop server mode, sessions can be resumed for about four hours with `claude remote-control --continue` ([docs](https://code.claude.com/docs/en/remote-control)). This is the closest free, zero-install answer to "control from phone + resume." It does not give you the multi-project sidebar or a ding.

**Claude Code Desktop app.** "each conversation is a session" and "each session gets its own isolated copy of your project using Git worktrees." Sidebar lists sessions; `Cmd+N` for a new one; OS notification "when a Code session finishes a task and you aren't currently viewing that session." Cloud sessions "continue even if you close the app or shut down your computer." macOS, Windows, Linux (beta) ([docs](https://code.claude.com/docs/en/desktop)). Good for many projects in a GUI; no terminal multiplexing; phone works through Remote Control.

**Claude Code `--worktree` + tmux (DIY).** `claude --worktree feature-auth` makes a worktree under `.claude/worktrees/` and starts Claude there. Add `.worktreeinclude` to copy `.env` files. Subagents can get `isolation: worktree`. Resume returns you to the same worktree ([docs](https://code.claude.com/docs/en/worktrees)). For the ding, use a `Notification` hook with matchers like `permission_prompt`, `idle_prompt`, `agent_needs_input`, `agent_completed`, or a `Stop` hook ([hooks docs](https://code.claude.com/docs/en/hooks)). Run it inside tmux for persistence. Free, but you build the glue yourself.

**Happy Coder.** "Mobile and Web Client for Codex and Claude Code, with realtime voice, encryption." `npm install -g happy`, then `happy claude` instead of `claude`. iOS, Android, web, macOS. "End-to-end encrypted." Push notifications when the agent needs permission. 23.7k stars, MIT. No pricing shown in README ([GitHub](https://github.com/slopus/happy)). Best pure phone client if you want no Anthropic-hosted transcript.

**Omnara.** Phone app to "run, monitor, and steer Claude Code and Codex sessions from your phone, web browser, Apple Watch." Apache 2.0 on GitHub. The website now positions it as "the open-source alternative to Claude Managed Agents" (a cloud agent platform), so the product is changing. A ~$9/month plan is reported by third parties, not confirmed by me on the official site ([omnara.com](https://omnara.com), [App Store](https://apps.apple.com/us/app/omnara-claude-codex-mobile/id6748426727), [GitHub](https://github.com/omnara-ai/omnara)).

**Conductor.** "Run parallel Claude Code, Codex, and Cursor agents in isolated workspaces on your Mac." Free tier = local workspaces, bring your own keys. Pro $50/mo adds Conductor Cloud and collab; Teams $60/user ([conductor.build](https://conductor.build), [pricing](https://conductor.build/pricing)). Mac only, not open source. Nice diff review. No terminal-first workflow.

**Vibe Kanban.** Plan / prompt / review board; `npx vibe-kanban`; 28k stars, Apache 2.0. Supports Claude Code, Codex, Gemini, Copilot, Amp, Cursor, OpenCode, and more. **"Vibe Kanban is sunsetting"** after Bloop AI shut down; now community maintained ([GitHub](https://github.com/BloopAI/vibe-kanban)). Risky to adopt now.

**claude-squad.** "a terminal app that manages multiple Claude Code, Codex, Gemini (and other local agents including Aider) in separate workspaces." Uses tmux for sessions and git worktrees for isolation. `brew install claude-squad`. 8.5k stars, AGPL-3.0 ([GitHub](https://github.com/smtg-ai/claude-squad)). Lean and terminal-only; no phone, no sound, no server model like Herdr.

**Crystal → Nimbalyst.** Crystal ("Run multiple Codex and Claude Code AI sessions in parallel git worktrees") is deprecated since Feb 2026 and replaced by Nimbalyst ([GitHub](https://github.com/stravu/crystal)). I could not fetch nimbalyst.com (blocked), so no price details.

**cmux.** "an open source Ghostty-based macOS terminal with vertical tabs and notifications for AI coding agents." 26.9k stars, GPL-3. Shows notification rings and badges when agents finish; SSH workspaces; restores windows and panes on relaunch; iOS beta app ([GitHub](https://github.com/manaflow-ai/cmux)). Closest GUI cousin of Herdr, Mac only. An HN commenter noted Herdr "will not call out to multiple web services upon start-up" unlike cmux ([HN](https://news.ycombinator.com/item?id=48714802)).

**Zellij.** Free open-source multiplexer. Session resurrection restores "the session layout (panes and tabs) and the command running in each pane", behind a "Press ENTER to run..." banner. Paid hosted session sharing (zellij.online) in beta ([zellij.dev](https://zellij.dev), [resurrection docs](https://zellij.dev/documentation/session-resurrection.html)). No agent-state awareness.

**tmux.** The classic. Free. Detach/reattach works. No agent states, no ding, mouse needs `set -g mouse on` (HN). Herdr uses the same `ctrl+b` prefix so your muscle memory moves over ([docs index](https://herdr.dev/docs/)).

**Warp.** Terminal app with its own agent ("Oz") and cloud agents. Free tier; Build $20/mo; Max $200/mo; Business $50/user ([pricing](https://www.warp.dev/pricing)). It can run Claude Code as a normal CLI, but its agent features push you to Warp's own agent and credits.

**Ghostty.** "a fast, feature-rich, and cross-platform terminal emulator." MIT, 60.9k stars, native tabs and splits. No background server or session persistence ([GitHub](https://github.com/ghostty-org/ghostty)). You can run Herdr *inside* Ghostty; they are not competitors.

## Recommendation for a Claude Code user who wants multi-project, resumable, notified

**Big picture:** Herdr does what Anthony showed, and it is free. But Claude Code already has two of the four things built in (resume, phone). So pick based on how much you live in the terminal.

**Option A — Herdr (what Anthony uses).** Best if you like the terminal and run more than one agent at a time.
1. `brew install herdr` ([install](https://herdr.dev/docs/install/)).
2. `herdr integration install claude` (and `pi` if you use it). Without this, chats do not resume after a reboot ([integrations](https://herdr.dev/docs/integrations/), [gist](https://gist.github.com/lasergoat/7f92d7c4ba72ee9889bb4b1fd6cd287a)).
3. Run `herdr`. Make one workspace per repo (`prefix+shift+n`). Start `claude` in a pane ([quick-start](https://herdr.dev/docs/quick-start/)).
4. Sound is already on. If you want popups too, set `[ui.toast] delivery = "system"` ([config-reference](https://herdr.dev/docs/config-reference/)).
5. For parallel tasks in one repo, use `herdr worktree create --branch my-task` so agents do not overwrite each other ([cli-reference](https://herdr.dev/docs/cli-reference/)).
6. Phone: install Moshi (free) and SSH to your Mac, or use Claude Code's own `/remote-control` inside the Herdr pane. Both work at the same time.
7. Know the limits: it is v0.9, pre-1.0. Windows and remote UI still have open bugs. It does not sandbox agents ([issues](https://github.com/herdrdev/herdr/issues), [coles.codes](https://coles.codes/posts/herding-agents-with-herdr/)).

**Option B — Stay pure Claude Code (no new tool).** Best if you mostly run one or two sessions.
- Resume from phone: `claude --remote-control` ([docs](https://code.claude.com/docs/en/remote-control)).
- Many projects side by side: Claude Code Desktop app, one session per worktree, OS notification when a session finishes ([docs](https://code.claude.com/docs/en/desktop)).
- Ding in the terminal: a `Notification` hook (matcher `permission_prompt` / `idle_prompt`) that plays a sound ([hooks docs](https://code.claude.com/docs/en/hooks)).
- What you miss: the one-screen sidebar of all agents across all projects, and agents spawning agents in visible panes.

**My pick for Larry:** Try Option A on your Mac for a week. It costs nothing, uses tmux keys, and you can still use `/remote-control` inside it. If the extra prefix keys annoy you (the most common HN complaint), fall back to Option B.

**What I am not sure about:**
- How Anthony set per-space git/LLM accounts and aliases. Not a documented Herdr feature; likely `--env` plus shell config. Ask him.
- Whether the socket-permission fix (issue #4) is fully solved; the issue is closed but I could not read the fix.
- Omnara's current pricing and direction; the site has pivoted.
- Herdr Cloud pricing; nothing official yet.
