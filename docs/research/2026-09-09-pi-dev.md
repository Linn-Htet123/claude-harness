# Research: pi / pi.dev (the minimal coding agent harness)

*Researched 2026-09-09. Every claim has a source link. Simple English, short sentences.*

## Summary (10 lines)

1. **pi** is a small, open-source (MIT) terminal coding agent by Mario Zechner ("badlogic", maker of libGDX). It now lives under the company **Earendil Inc.** at https://pi.dev and https://github.com/earendil-works/pi (old URL `badlogic/pi-mono` redirects there). [pi.dev](https://pi.dev), [GitHub API](https://api.github.com/repos/earendil-works/pi)
2. It is huge: **103,436 stars, 12,924 forks**, created Aug 9 2025, last push Sept 9 2026. [GitHub API](https://api.github.com/repos/earendil-works/pi)
3. Core idea: "primitives, not features". Only 4 tools (read, write, edit, bash), system prompt under 1,000 tokens. No MCP, no sub-agents, no plan mode, no permission popups, no todo list, no background bash **built in**. You add them as extensions. [README](https://raw.githubusercontent.com/earendil-works/pi/main/packages/coding-agent/README.md), [Mario's blog](https://mariozechner.at/posts/2025-11-30-pi-coding-agent/)
4. Extensions are TypeScript files in `~/.pi/agent/extensions/` or `.pi/extensions/`. They can add tools, slash commands, hooks on events (like `tool_call`), UI, and sub-sessions. [extensions.md](https://raw.githubusercontent.com/earendil-works/pi/main/packages/coding-agent/docs/extensions.md)
5. There is a big package ecosystem (5,600+ packages on pi.dev/packages). Top ones: `pi-mcp-adapter` (761K downloads/month), `pi-subagents` (362K/mo), `pi-web-access`. [pi.dev/packages](https://pi.dev/packages)
6. **"First mate"** = `kunchenguid/firstmate` (5.3k stars). One "first mate" agent dispatches worker agents into git worktrees, supervises them, and reports back. Works with Claude Code, pi, Codex, OpenCode, Cursor. [firstmate](https://github.com/kunchenguid/firstmate)
7. **"Wayfinder"** = the `/wayfinder` skill from Matt Pocock's `mattpocock/skills` (257k stars). It builds a "map" issue plus decision tickets on GitHub Issues / Linear / Jira. It is a skill, not a pi extension. It installs into Claude Code too. [wayfinder.md](https://github.com/mattpocock/skills/blob/main/docs/engineering/wayfinder.md), [mattpocock/skills](https://github.com/mattpocock/skills)
8. Cost: Databricks found pi sends ~3x less context per turn than Claude Code/Codex and cost ~50% less per task with same quality. [Databricks blog](https://www.databricks.com/blog/benchmarking-coding-agents-databricks-multi-million-line-codebase)
9. Pain points people report: "assembly required", no safety rails by default, Windows problems, docs gaps, and API-key costs vs a Claude subscription. [HN](https://news.ycombinator.com/item?id=47143754), [Windows thread](https://github.com/earendil-works/pi/issues/7547)
10. Most reviewers still use Claude Code daily and pi on the side. [Composio](https://composio.dev/content/pi-agent-vs-claude-code)

## 1. What pi is

### One-line
"There are many agent harnesses—but this one is yours." pi calls itself "a minimal agent harness" and says "Adapt Pi to your workflows, not the other way around." [pi.dev](https://pi.dev)

### Who makes it
- Author: Mario Zechner (badlogic). He wrote it because Claude Code "accumulated complexity he didn't need" and he wanted full control of context. [Mario's blog, Nov 30 2025](https://mariozechner.at/posts/2025-11-30-pi-coding-agent/)
- Now maintained by **Earendil Inc.**, a company that "crafts tools to harness AI" with products Pi and Lefos. [earendil.com](https://earendil.com)
- The npm package moved from `@mariozechner/pi-coding-agent` to `@earendil-works/pi-coding-agent` in May 2026 at v0.74.0 (secondary source). [ghtrends](https://ghtrends.dev/earendil-works/pi/)
- Discord: https://discord.com/invite/3cU7Bz4UPx. X: https://x.com/pidotdev. [pi.dev](https://pi.dev)

### Architecture (packages in the monorepo)
| Package | What it does |
|---|---|
| `@earendil-works/pi-ai` | One API for many LLM providers (streaming, tool calls, cross-provider handoff) |
| `@earendil-works/pi-agent-core` | The agent loop: tool calling, state, events |
| `@earendil-works/pi-tui` | Terminal UI library with differential rendering |
| `@earendil-works/pi-coding-agent` | The CLI you run: sessions, tools, extensions, skills |
| `@earendil-works/chord` | "Application composition runtime for services and plugins" |
| `@earendil-works/pi-telemetry` | Vendor-neutral telemetry schemas |

Source: [repo README](https://github.com/earendil-works/pi), [Mario's blog](https://mariozechner.at/posts/2025-11-30-pi-coding-agent/)

- **Web UI?** There is no official web UI package. pi has a session share viewer at `pi.dev/session/#...` (via `/share`, uploads a private GitHub gist). [pi.dev](https://pi.dev), [sessions.md](https://raw.githubusercontent.com/earendil-works/pi/main/packages/coding-agent/docs/sessions.md). A separate repo `pi-chat` does Slack/chat automation. [repo README](https://github.com/earendil-works/pi). Community built a web GUI called ThinkRail. [discussions](https://github.com/earendil-works/pi/discussions)
- **OpenClaw** (the very popular agent, ex-Clawdbot) embeds pi's SDK directly via `createAgentSession()`. It does not use RPC. [dev.to](https://dev.to/jiade/inside-openclaw-how-the-worlds-fastest-growing-ai-agent-actually-works-under-the-hood-4p5n), [Armin Ronacher](https://lucumr.pocoo.org/2026/1/31/pi/)

### Four run modes
1. Interactive TUI (default)
2. Print mode `-p` (one shot, pipe-friendly)
3. JSON mode `--mode json` (JSONL event stream)
4. RPC mode `--mode rpc` (JSON over stdin/stdout, for editors and orchestrators)
5. SDK: `createAgentSession()` in TypeScript

Source: [README](https://raw.githubusercontent.com/earendil-works/pi/main/packages/coding-agent/README.md), [rpc.md](https://raw.githubusercontent.com/earendil-works/pi/main/packages/coding-agent/docs/rpc.md), [sdk.md](https://raw.githubusercontent.com/earendil-works/pi/main/packages/coding-agent/docs/sdk.md)

### Built-in tools and context
- Default tools: `read`, `write`, `edit`, `bash`. Extra discovery tools: `grep`, `find`, `ls`, and `powershell` on Windows. [README](https://raw.githubusercontent.com/earendil-works/pi/main/packages/coding-agent/README.md)
- System prompt is under 1,000 tokens (Claude Code was 10,000+ at the time). [Mario's blog](https://mariozechner.at/posts/2025-11-30-pi-coding-agent/)
- Context files: `AGENTS.md` or `CLAUDE.md` (global in `~/.pi/agent/`, plus parent dirs, plus cwd). `.pi/SYSTEM.md` replaces the system prompt for a project. [README](https://raw.githubusercontent.com/earendil-works/pi/main/packages/coding-agent/README.md)
- Sessions are JSONL **trees** (each entry has `id` + `parentId`). `/tree` to branch in place, `/fork`, `/clone`, `/compact`. [sessions.md](https://raw.githubusercontent.com/earendil-works/pi/main/packages/coding-agent/docs/sessions.md)
- Steering: press Enter while it runs to steer; Alt+Enter to queue a follow-up. [pi.dev](https://pi.dev)

### Providers / models
"Anthropic, OpenAI, Google, Azure, Bedrock, Mistral, Groq, Cerebras, xAI, Hugging Face, Kimi For Coding, MiniMax, NVIDIA, OpenRouter, Ollama, and more." Login with API keys or OAuth. Subscriptions supported: Claude Pro/Max, ChatGPT Plus/Pro, GitHub Copilot. Custom providers via `~/.pi/agent/models.json` or an extension. Switch model mid-session with `/model` or Ctrl+L. [pi.dev](https://pi.dev), [README](https://raw.githubusercontent.com/earendil-works/pi/main/packages/coding-agent/README.md)

### What pi deliberately leaves out (and why)
| Not built in | Mario's reason |
|---|---|
| MCP | MCP servers dump big tool lists into context (7-9% of window). Use CLI tools + a README/skill, or add an MCP extension. |
| Sub-agents | "Black boxes within black boxes." Spawn a new `pi` process via bash instead, so you can see everything. |
| Plan mode | Write the plan to a file (PLAN.md). Files are visible and version-controlled. |
| Todo tool | "To-do lists confuse models." Use TODO.md. |
| Permission popups | Run in a container. Or build a `tool_call` gate extension. |
| Background bash | Use tmux. |

Source: [Mario's blog](https://mariozechner.at/posts/2025-11-30-pi-coding-agent/), [README](https://raw.githubusercontent.com/earendil-works/pi/main/packages/coding-agent/README.md), [MCP post](https://mariozechner.at/posts/2025-11-02-what-if-you-dont-need-mcp/)

Mario on X (seen in search snippets, could not fetch the post itself): "still not using subagents, but i'm glad pi's extensibility allows others to go nuts." (Mar 30 2026) [x.com](https://x.com/badlogicgames/status/2038613964024578499)

### How pi differs from Claude Code / Codex / OpenCode
| | pi | Claude Code | Codex CLI | OpenCode |
|---|---|---|---|---|
| Open source | MIT | No | Apache-2.0 | Yes |
| Providers | 15+, switch mid-session | Claude only | OpenAI (ChatGPT login or API key) | Many |
| System prompt overhead | <1,000 tokens | ~10-14k (older), less on Claude 5 | - | ~6,900 tokens |
| Plan mode | Extension | Built in | - | Built in (Tab) |
| Sub-agents | Extension / bash spawn | Built in | - | Built in |
| MCP | Extension (`pi-mcp-adapter`) | Built in | - | Built in |
| Permissions | None by default; extension or container | Built in | Sandbox | Built in |
| Sessions | Tree (branch/fork) | Linear | - | - |

Sources: [Composio pi vs Claude Code, Sep 4 2026](https://composio.dev/content/pi-agent-vs-claude-code), [Composio pi vs OpenCode, Aug 21 2026](https://composio.dev/content/pi-vs-opencode), [bswen 4-way, Aug 10 2026](https://docs.bswen.com/blog/2026-08-10-pi-vs-claude-code-vs-codex-vs-opencode/), [Codex repo](https://github.com/openai/codex), [OpenCode docs](https://opencode.ai/docs/)

Benchmarks (secondary sources):
- Composio, 30 hard tasks, DeepSeek V4 Flash: pi 20/30 at $0.028 per success; Claude Code 16/30 at $0.195 per success. Scorecard "Pi 6, Claude Code 5". But: "Even the biggest Pi fans ship most of their work through Claude Code." [Composio](https://composio.dev/content/pi-agent-vs-claude-code)
- Composio pi vs OpenCode: pi 21/30, OpenCode 19/30. pi slower (363s vs 281s median). "6-6 dead tie". [Composio](https://composio.dev/content/pi-vs-opencode)
- Databricks (Jul 8 2026): pi ~50% cheaper per task, same quality; Claude Code/Codex fed ~3x more context per turn. With Opus 4.8 xhigh, pi had the highest pass rate. [Databricks](https://www.databricks.com/blog/benchmarking-coding-agents-databricks-multi-million-line-codebase), [Earendil post](https://earendil.com/posts/pi-autoresearch-and-databricks/)

Sources: [README](https://raw.githubusercontent.com/earendil-works/pi/main/packages/coding-agent/README.md), [extensions.md](https://raw.githubusercontent.com/earendil-works/pi/main/packages/coding-agent/docs/extensions.md), [packages.md](https://raw.githubusercontent.com/earendil-works/pi/main/packages/coding-agent/docs/packages.md), [subagent example](https://raw.githubusercontent.com/earendil-works/pi/main/packages/coding-agent/examples/extensions/subagent/README.md)

Project-local extensions only load after you trust the project (`/trust`). [extensions.md](https://raw.githubusercontent.com/earendil-works/pi/main/packages/coding-agent/docs/extensions.md)

### How to write an extension
One TypeScript file. Export a default function that gets `ExtensionAPI`. Loaded with jiti, so no build step. Test one with `pi -e ./my-ext.ts`.

```ts
import type { ExtensionAPI } from "@earendil-works/pi-coding-agent";

export default function (pi: ExtensionAPI) {
  pi.on("tool_call", async (event, ctx) => {
    if (event.toolName === "bash" && event.input.command?.includes("rm -rf")) {
      const ok = await ctx.ui.confirm("Dangerous!", "Allow rm -rf?");
      if (!ok) return { block: true, reason: "Blocked by user" };
    }
  });
  pi.registerTool({ name: "my_tool", /* params, execute() */ });
  pi.registerCommand("mycommand", { /* ... */ });
}
```

Key API: `pi.on(event)`, `pi.registerTool()`, `pi.registerCommand()`, `pi.registerShortcut()`, `pi.sendMessage()`, `pi.appendEntry()` (state that survives restart), `pi.setActiveTools()`, `pi.setModel()`, `pi.registerProvider()`, `pi.registerMessageRenderer()`.
Events (these are pi's "hooks"): `session_start`, `session_shutdown`, `before_agent_start` (inject messages, change system prompt), `input`, `tool_call` (can block = permission gate), `tool_execution_start/end`, `agent_start/end/settled`.
Handlers get `ctx` with `ctx.ui.confirm/select/notify`, `ctx.sessionManager`, `ctx.cwd`, `ctx.newSession()`, `ctx.switchSession()`.
Source: [extensions.md](https://raw.githubusercontent.com/earendil-works/pi/main/packages/coding-agent/docs/extensions.md)

### Skills
Follow the Agent Skills standard. A folder with `SKILL.md` (frontmatter `name`, `description`, optional `allowed-tools`). Only the name + description go in the system prompt. The model reads the full file when needed ("progressive disclosure"). Call by hand with `/skill:name`. [skills.md](https://raw.githubusercontent.com/earendil-works/pi/main/packages/coding-agent/docs/skills.md)
Mario's own skills repo (browser tools, YouTube transcript, Gmail CLI, etc.) also works in Claude Code and Codex: [badlogic/pi-skills](https://github.com/badlogic/pi-skills) (2.5k stars).

### Prompt templates and themes
- Prompts: markdown files with `{{variable}}`. Run as `/templatename`. [README](https://raw.githubusercontent.com/earendil-works/pi/main/packages/coding-agent/README.md)
- Themes: JSON in `~/.pi/agent/themes/`, hot reload. [README](https://raw.githubusercontent.com/earendil-works/pi/main/packages/coding-agent/README.md)

### Packages
Bundle extensions + skills + prompts + themes. Publish to npm (keyword `pi-package`) or git.
```
pi install npm:@foo/pi-tools
pi install git:github.com/user/repo@v1
pi install ./local/path
```
`package.json` gets a `"pi": { "extensions": [...], "skills": [...], ... }` key. Use `pi config` to turn things on/off. Project settings override global. Warning from the docs: "Pi packages run with full system access." [packages.md](https://raw.githubusercontent.com/earendil-works/pi/main/packages/coding-agent/docs/packages.md), [README](https://raw.githubusercontent.com/earendil-works/pi/main/packages/coding-agent/README.md)

Highlights: `subagent/`, `plan-mode/`, `sandbox/` (uses `@anthropic-ai/sandbox-runtime`), `gondolin/` (micro-VM), `permission-gate`, `protected-paths`, `confirm-destructive`, `dirty-repo-guard`, `todo`, `question`, `git-checkpoint`, `auto-commit-on-exit`, `handoff`, `custom-compaction`, `event-bus`, `github-issue-autocomplete`. [examples dir](https://github.com/earendil-works/pi/tree/main/packages/coding-agent/examples/extensions)

### How people do sub-agents
1. **Official example `subagent/`**: each sub-agent is a separate `pi` process. Agent definitions are markdown files in `~/.pi/agent/agents/*.md` or `.pi/agents/*.md`. Modes: single, parallel (max 8 tasks, 4 at once), chain (with `{previous}` placeholder). Results return to the parent model, capped at 50 KB per task. [subagent README](https://raw.githubusercontent.com/earendil-works/pi/main/packages/coding-agent/examples/extensions/subagent/README.md)
2. **Bash spawn (Mario's way)**: "If you need pi to spawn itself, just ask it to run itself via bash" with `pi --print`. Full observability. [Mario's blog](https://mariozechner.at/posts/2025-11-30-pi-coding-agent/)
3. **SDK**: `createAgentSession({ cwd, tools: ["read","bash"], sessionManager: SessionManager.inMemory() })` for child sessions in code. [sdk.md](https://raw.githubusercontent.com/earendil-works/pi/main/packages/coding-agent/docs/sdk.md)
4. **Community packages** (see table below).

### How people do plan mode

- **Permissions / security**: "Pi does not include a built-in permission system." Project trust "is not a sandbox." Advice: run in a container, VM, or micro-VM. Prompt injection from repo files is "expected local-agent risk." [security.md](https://raw.githubusercontent.com/earendil-works/pi/main/packages/coding-agent/docs/security.md), [repo README](https://github.com/earendil-works/pi)
- **Env vars**: `PI_CODING_AGENT_DIR`, `PI_CODING_AGENT_SESSION_DIR`, `PI_OFFLINE`, `PI_TELEMETRY`, `PI_CACHE_RETENTION`, plus `PI_SESSION_ID`, `PI_MODEL` set inside bash tool calls. [README](https://raw.githubusercontent.com/earendil-works/pi/main/packages/coding-agent/README.md)

## 6. "Wayfinder": what exists

**Match found.** "Wayfinder" is the `/wayfinder` skill in Matt Pocock's **mattpocock/skills** (257.7k stars, MIT). This matches Anthony's description almost exactly (project map -> tasks -> Linear / GitHub Issues).

- What it does: "takes an effort too big for one agent session... and charts it as a shared map of decision tickets on your issue tracker, then resolves them one at a time." It "plans, it does not do." [wayfinder.md](https://github.com/mattpocock/skills/blob/main/docs/engineering/wayfinder.md)
- The map = one issue labeled `wayfinder:map` with: Destination, Decisions so far, "Not yet specified" (the "fog of war"), Out of scope. Child issues are decision tickets with labels `wayfinder:grilling` (default, talk with you), `wayfinder:prototype`, `wayfinder:research` (AFK), `wayfinder:task`. Sub-issues carry blocking links. [wayfinder.md](https://github.com/mattpocock/skills/blob/main/docs/engineering/wayfinder.md), [aihero](https://www.aihero.dev/skills-wayfinder)
- Trackers: GitHub Issues (best, native sub-issues + blocking), GitLab, **Linear**, Jira, local markdown. [wayfinder.md](https://github.com/mattpocock/skills/blob/main/docs/engineering/wayfinder.md)
- Pipeline: `/wayfinder` -> `/to-spec` -> `/to-tickets` -> `/implement`. Use it only when the work is bigger than one session; otherwise `/grill-me` is cheaper. [wayfinder.md](https://github.com/mattpocock/skills/blob/main/docs/engineering/wayfinder.md)
- Install for Claude Code: `claude plugins install mattpocock-skills` or `/plugin install mattpocock-skills`. For any agent (Codex, pi, OpenCode...): `npx skills@latest add mattpocock/skills --skill=wayfinder`. Then run `/setup-matt-pocock-skills` once per repo to pick the tracker (GitHub, Linear, or local files). [mattpocock/skills](https://github.com/mattpocock/skills), [aihero](https://www.aihero.dev/skills-wayfinder)
- Other things named "wayfinder" on npm are unrelated to this (a code-navigation tool, a model-router display, and `pi-wayfinder-guard` which "enforces no-implementation during wayfinder (fog mode)" - that one is a companion to Matt's skill). [npm search](https://registry.npmjs.org/-/v1/search?text=keywords:pi-package%20wayfinder&size=15)
- No package named "wayfinder" is in the pi.dev catalog. [pi.dev/packages](https://pi.dev/packages?q=wayfinder)

Note: Wayfinder makes **decision** tickets, not build tickets. `/to-tickets` makes the build tickets. Anthony's "Wayfinder outputs tasks to Linear" likely means the whole chain (wayfinder -> to-spec -> to-tickets).

## 7. Alternatives for "minimal, build your own harness"

**OpenCode** (https://opencode.ai, https://github.com/anomalyco/opencode). Open-source, any provider, terminal + desktop + IDE extension. Ships plan mode (Tab), sub-agents, MCP, LSP, permissions, plugins, Agent Skills, `AGENTS.md`. More "product" than pi: "OpenCode gives you configuration control. Pi gives you runtime control." ~6,900 tokens of overhead per request. $10/month "Go" plan for open models. Good if you want most features ready and still want to switch models. [OpenCode docs](https://opencode.ai/docs/), [Composio](https://composio.dev/content/pi-vs-opencode)

**Codex CLI** (https://github.com/openai/codex). OpenAI's open-source (Apache-2.0) terminal agent, ~122.8k stars. Login with ChatGPT plan or API key. Runs locally, plus IDE and cloud versions. Locked to OpenAI models, so less flexible than pi; seen on HN as "reliable". [Codex repo](https://github.com/openai/codex), [HN](https://news.ycombinator.com/item?id=47143754)

**Claude Agent SDK** (https://code.claude.com/docs/en/agent-sdk/overview). "Build production AI agents with Claude Code as a library" in Python or TypeScript. You get the same agent loop, built-in tools, hooks, subagents, MCP, permissions, sessions (resume/fork), skills, plugins. This is the closest "build your own harness" option that stays inside Claude. Note: API-key billing; third parties may not offer claude.ai login unless approved. Managed Agents is the hosted version. [Agent SDK docs](https://code.claude.com/docs/en/agent-sdk/overview)

**Amp** (https://ampcode.com/manual). Sourcegraph's agent. Not open source per its manual. Multi-model, "Orbs" (isolated machines per thread), shareable threads, Skills, MCP, Plugins. Opinionated and fast-moving ("no backward compatibility constraints"). Less DIY than pi. [Amp manual](https://ampcode.com/manual)

**Crush** (https://github.com/charmbracelet/crush). Charm's Go TUI agent, 28k+ stars, FSL-1.1-MIT license. Many providers, LSP context, MCP (stdio/HTTP/SSE), multiple sessions per project, Agent Skills, model switching mid-chat. Pretty and batteries-included; not built for in-process extensions like pi. [Crush repo](https://github.com/charmbracelet/crush)

**Goose** (https://github.com/block/goose). Block's Rust agent, 54.1k stars, Apache-2.0, in the Linux Foundation's Agentic AI Foundation. Desktop app + CLI + API, 15+ providers, 70+ MCP extensions, "recipes" for workflows, custom distributions. General-purpose (not only code). Heavier than pi, but a solid open base. [Goose repo](https://github.com/block/goose)

**oh-my-pi** (https://github.com/can1357/oh-my-pi). Fork of pi with batteries: LSP on every edit, debuggers, sub-agents in worktrees, 31 tools, 60+ providers. 30.4k stars. If pi is too bare, this is the middle path. Also a verified firstmate primary. [oh-my-pi](https://github.com/can1357/oh-my-pi), [firstmate](https://github.com/kunchenguid/firstmate)

**firstmate** (see section 2) is not a harness. It is a "distro" that sits on top of Claude Code / pi / Codex and gives you the coordinator-plus-crew pattern out of the box. [firstmate](https://github.com/kunchenguid/firstmate)

## 8. What Larry could copy from Anthony's setup, in Claude Code

Big picture: Anthony built (a) a map of the project in the tracker, (b) one coordinator session, (c) worker agents in worktrees, (d) a fixed 4-step loop per task, (e) Linear updates via MCP. Claude Code already has most of the pieces built in. Ideas, cheapest first:

1. **Install Wayfinder + friends (10 min).** `claude plugins install mattpocock-skills`, then `/setup-matt-pocock-skills` in `manifest-movies-next` and pick Linear. Now `/wayfinder` -> `/to-spec` -> `/to-tickets` writes the map and tickets into Linear. This is literally the tool Anthony named. [mattpocock/skills](https://github.com/mattpocock/skills). Ask Eric/Anthony first, because it creates Linear issues (team data).
2. **Keep the map in the tracker, not in chat.** Wayfinder's key trick: the context lives in a `wayfinder:map` issue, so it survives sessions and the whole team can see it. Same idea as `TECH-TRUTH.md` in the vault. [wayfinder.md](https://github.com/mattpocock/skills/blob/main/docs/engineering/wayfinder.md)
3. **Use the Linear MCP you already have.** Claude Code has MCP built in. Anthony's "state updates automatically" = the agent calls Linear tools when a step finishes. Put that rule in the project `CLAUDE.md` ("after tests pass, move the Linear issue to In Review and add a comment with the PR link").
4. **Write the 4-step loop as a skill.** Make `.claude/skills/task-loop/SKILL.md` with the 4 steps (for example: 1 read ticket + plan, 2 implement in worktree, 3 verify with tests + screenshot, 4 update Linear + open PR). Claude Code's skills use the same Agent Skills standard as pi. [skills.md](https://raw.githubusercontent.com/earendil-works/pi/main/packages/coding-agent/docs/skills.md)
5. **Sub-agents in worktrees.** Claude Code's Agent tool supports `isolation: "worktree"` and named agent types (`.claude/agents/*.md`). Copy firstmate's split: "ship" workers (write code, open PR) and "scout" workers (research only, return a report). Give research agents read-only tools so they cost less and cannot break things. [firstmate](https://github.com/kunchenguid/firstmate)
6. **Thin coordinator context.** From agent-fleet and firstmate: workers write results to a file and send back only a one-line summary + path. The coordinator stays small and cheap. [agent-fleet](https://github.com/chankov/agent-fleet), [firstmate architecture](https://github.com/kunchenguid/firstmate/blob/main/docs/architecture.md)
7. **Verification agent = separate agent.** Anthony's "verification" sub-agent matches pi-subagents' `reviewer` / `evidence-auditor` roles and firstmate's "no-mistakes" gate (adversarial review + tests + lint before merge). Fits Larry's "triple-check before done" rule. [pi-subagents](https://github.com/nicobailon/pi-subagents), [sudoall](https://sudoall.com/talk-to-one-agent-first-mate-agentic-stack/)
8. **Plan in files, not only in chat.** Mario's habit: PLAN.md / TODO.md in the repo. Cheap, visible, git-tracked. Pairs well with spec-first. [Mario's blog](https://mariozechner.at/posts/2025-11-30-pi-coding-agent/)
9. **Try firstmate itself later.** It runs on Claude Code with a Stop hook. But it needs tmux/WezTerm and setup time; the SudoAll review says it is overhead for single-session work. Good to try only after steps 1-7 feel natural. [firstmate](https://github.com/kunchenguid/firstmate), [sudoall](https://sudoall.com/talk-to-one-agent-first-mate-agentic-stack/)
10. **Do not switch to pi just for this.** pi's win is cost + control when you pay per token or switch models. Larry's team rules (no push to main, migrate only, Becca sign-off) are easier to enforce with Claude Code's built-in permissions and hooks than with pi's "YOLO by default". [security.md](https://raw.githubusercontent.com/earendil-works/pi/main/packages/coding-agent/docs/security.md)
